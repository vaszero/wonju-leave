① 5단계 비교 · 프로젝트 만들기 (1교시)

채팅 → 챗봇 → 스킬 → 코워크 → 코드, 다섯 단계가 무엇을 기억하고 무엇을 만드는지 비교합니다.
  • 채팅 — 자료·규칙·요청을 매번 전부 알려줘야 하고, 결과는 답 하나뿐. 예: "이 계획안 문장 다듬어 줘"
  • 챗봇 — 요청만 하면 되고, 자료·배경을 기억한다(그 방 안에서만). 예: 지식베이스를 넣은 '센터 문서방'
  • 스킬 — 파일만 주면 되고, 일하는 규칙·순서를 기억한다(어느 방에서든). 예: /계획안 → 규칙 블록 자동 적용
  • 코워크 — 업무의 끝 한 줄만 주면, 폴더 전체를 기억하고 파일로 완성한다. 예: "3개 사업 결과보고서, 폴더에 만들어 줘"
  • 코드 — 만들고 싶은 도구를 말하면 저장소로 앱을 완성한다 — 오늘 7교시에 실습

오늘의 한 문장 — "답을 요청하지 말고 결과를 요청한다." 채팅은 답을 받고, 챗봇은 설명을 안 하고, 스킬은 방식을 안 알려주고, 코워크는 내가 일을 덜한다.

② 회의록 스킬 center-minutes 만들기 (2교시 · 15분)

규칙 블록을 스킬로 바꿔, 녹취 텍스트를 hwpx 회의록으로 자동 정리한다.
  1. 설정 → 사용자 지정 → 스킬 → 추가 → 스킬 만들기
  2. 이름칸에 center-minutes 입력
  3. 설명칸에 아래 S-1, 지침칸에 S-2를 복사해서 붙여넣기
  4. '만들기' → 새 채팅에서 /center-minutes + 아래 재료(녹취)를 붙여넣고 확인

S-1 — 스킬 설명

센터 회의 녹취(클로바노트 텍스트)를 붙여넣으면 잡담을 걸러내고 화자를 직위로 정리해 결정·미결·향후 일정 형식의 회의록을 hwpx 파일로 만든다.

S-2 — 지침 다섯 덩어리

① 화자 정리 호칭과 발언 내용으로 직위를 추정해서 표시한다. 실명은 쓰지 않는다. 추정한 직위 뒤에는 항상 "(추정)"을 붙인다. ② 걸러낼 것 잡담·반복·추임새는 제거한다. 단, 잡담처럼 보여도 일정(날짜·시간)이 섞여 있으면 남긴다. ③ 구성 항상 "개요 → 논의 → 결정 → 미결 → 향후 일정 → 집계 한 줄" 순서로 정리한다. ④ 판단 규칙 결정은 "무엇을·누가·언제까지"가 모두 있어야 결정으로 본다. "확인했다", "그대로 하기로" 같은 발언은 결정이 아니라 확인이므로 결정 표에 넣지 않는다. ⑤ 출력 항상 hwpx 파일로 만든다. 채팅창에는 결정 건수와 미결 건수만 요약해서 보여준다.

재료 — 연습용 녹취 텍스트 (함정: 화자 표시 없음 · 커피·점심 같은 잡담 · "강사료 그대로예요"는 결정이 아니라 확인 · 캠페인 장소는 미결로 남겨야 함)

자, 시작할까요. 다 오셨죠. 아 커피 드셨어요? 아래 카페 오늘 문 닫았더라고요. 네 그럼 오늘 안건이 세 개죠. 게이트키퍼 교육 일정하고, 치료비 지원 예산 집행 현황하고, 그 다음에 다음 달 캠페인. 팀장님이 먼저 교육 쪽 해주세요. 네. 게이트키퍼 교육이요, 원래 5월 14일이었는데 강사님이 그날 도교육청 일정이 잡혔대요. 그래서 21일이나 28일로 옮겨야 되는데. 28일은 저희 사례관리 회의랑 겹치고요. 그럼 21일로 가죠. 21일 목요일 맞죠? 네 목요일이요. 아 근데 21일이면 교육실 예약이... 그건 제가 확인해볼게요. 제가 사례관리 쪽인데 그날 오후는 저희 비어요. 오전만 아니면 돼요. 그럼 오후 2시로. 네 2시요. 통반장 모집은 몇 명이에요 지금. 지금 19명이요. 30명 목표인데. 음. 면사무소에 공문 다시 보내야 되나. 저번에 보낸 게 3월인데 반응이 없어서요. 그러면 공문 한 번 더 보내고, 이번엔 전화도 같이 돌리죠. 전화는 누가... 제가 할게요, 사례관리 쪽에서 면사무소랑 원래 통화 자주 하니까. 네 그럼 그렇게 하고. 언제까지요? 교육 2주 전이니까 5월 7일까지는 명단이 나와야죠. 네. 아 잠깐, 그 강사님 강사료 그대로예요? 네 회당 20만원 그대로요. 알겠어요. 두 번째, 치료비 지원이요. 센터장님 이거 지금 집행률이 4월 말 기준 38프로예요. 작년 이맘때 45였는데. 좀 낮네요. 신청이 줄었나요? 신청은 비슷한데 심사에서 반려가 좀 있었어요. 소득 기준 서류가 안 맞아서요. 그거 안내문에 서류 목록을 좀 더 자세히 넣어야 될 것 같아요. 네 그건 담당 선생님이 안내문 고쳐서 다음 주 회의 때 가져오세요. 네 다음 주 화요일이요. 예산 추가 배정은 아직 얘기할 단계는 아닌 것 같고, 6월 말 집행률 보고 다시 얘기하죠. 네. 아 그리고 저번에 얘기한 홈페이지 신청 서식 파일이 아직 hwp라서요, 사람들이 스마트폰에서 못 연다고. 그거는... 일단 pdf로도 같이 올려놓죠. 누가 올려요? 그건 저희 팀에서요. 네. 세 번째 캠페인. 다음 달 9월 10일 자살예방의 날이잖아요. 작년처럼 원주역 광장에서 할지, 아니면 올해는 중앙시장으로 갈지. 시장 쪽이 유동인구는 많은데 상인회 협조가 필요해요. 그거는 좀 알아봐야 될 것 같은데. 상인회 연락처는 있어요? 작년 담당자가 갖고 있을 텐데 지금 없어서... 음. 이건 오늘 결정 못 하겠네요. 장소는 다음 주까지 두 군데 다 알아보고 다시 얘기하죠. 현수막이랑 리플릿은 장소 정해지고 나서 하는 걸로. 네. 아 그리고 인턴 선생님 다음 주부터 오시는 거 맞죠? 네 월요일이요. 자리는 창가 쪽으로. 알겠습니다. 더 있어요? 없으면 마치죠. 다음 회의는 다음 주 화요일 같은 시간. 수고하셨습니다. 아 점심 뭐 먹어요.

③ 계획안 스킬 center-plan 만들기 (2교시 · 그대로 붙여넣기)

어제 규칙 블록으로 쓰던 계획안을 스킬로 옮긴 두 번째 예시. 이번엔 설명 없이 바로 복사해서 넣어 봅니다.

P-1 — 스킬 설명 (스킬 이름: center-plan)

원주시정신건강복지센터 내부 계획안(내부결재 공문 + 붙임1 계획안)을 작성할 때 사용. 마스터 시트의 사업 정보를 입력받아 센터 계획안 양식 순서와 문서 규칙에 맞는 텍스트를 만들고, 요청하면 첨부 양식(hwpx)에 채워 저장한다.

P-2 — 지침

너는 원주시정신건강복지센터 사업 담당자다. 센터 내부 계획안 양식을 채운다. [입력] 마스터 시트 내용: 사업명, 일시, 대상, 필요성 근거(통계·전년도 결과·개선과제), 목적, 사업 내용, 예산 항목(항목·산출기초·금액), 일정, 역할분담, 평가 방법. 빠진 항목은 "[확인 필요]"로 표시하고 지어내지 않는다. [문서 구성 — 이 순서를 바꾸지 않는다] A. 내부결재 공문 (앞장) 수신자: 내부결재 / 제목: ○○○○년 ○○○ 계획 본문: 계획 배경 한 문단으로 시작해 "~계획하였기에 보고합니다."로 맺는다. 이어서 1. 일시 2. 대상 3. 내용 세 줄, 그 아래 "붙임 1. ○○○ 1부. 끝." B. [붙임1] 계획안 제목(15pt) → 1. 필요성 → 2. 목적 → 3. 사업 내용 → 4. 예산 → 5. 진행 및 역할분담 (가. 진행 절차 표, 나. 역할분담 표) → 6. 평가 → 7. 기대효과 1. 필요성에는 시트의 근거(통계·전년도 결과·개선과제) 중 최소 1개를 문장에 넣는다. [문서 규칙] - 맑은 고딕, 제목 15pt, 본문 11pt, 줄간격 160%, 검정 - 번호: 1. → 가. → 1) → 가) → (1). 수준마다 2칸씩 들여쓰기 - 개조식 "~함/~임". 공문 본문만 "~합니다" 경어체 - 사람 이름 대신 직위(센터장, 부센터장, 팀장, 담당). 역할분담 표도 직위로 쓴다 - 예산표는 구분·산출기초·금액 3열. 산출기초는 "단가 × 수량 × 횟수" 형태로 시트 값을 그대로 쓴다. 총계는 계산하지 않고 비워 둔다 - 진행 절차 표는 세로 항목(단계) × 가로 날짜. 날짜는 시트 일정만 사용 [출력] - 기본: 한글에 붙여넣을 텍스트. 설명·인사말·마크다운 기호 없이 문서 본문만. 표는 탭 구분 - "hwpx로"라고 하면: 첨부된 계획안 양식.hwpx의 칸을 채워 hwpx 파일로 저장한다. 양식 구조·결재선·표 틀은 바꾸지 않는다 [금지] 시트에 없는 수치·근거·일정을 만들지 않는다. 합계를 계산하지 않는다. 양식의 예시 문장(자살예방 치료비 지원 등)을 결과에 남기지 않는다.

설정 → 사용자 지정 → 스킬 → 추가 → 스킬 만들기 → 이름 center-plan → 설명 P-1, 지침 P-2 붙여넣기 → 만들기.

큰 행동 전에는 항상 승인 창이 먼저 뜹니다 — 확인 없이 실행되지 않습니다.

⑥ Claude Design — 성과 시각화 (5교시)

말로 시키면 초안이 나오고, 나온 결과를 클릭해서 직접 수정한다.
  • 캔바는 템플릿을 골라 내가 채우고, Design은 말로 시키면 초안이 나온다
  • 나온 결과는 클릭해서 글자·색·위치를 직접 수정할 수 있다
  • 디자인 시스템을 등록해 두면 색·서체가 모든 시안에 자동 적용된다
  • 내보내기는 이미지·PDF뿐 아니라 PPTX·코드까지 — 캔바로 마무리해도 된다

템플릿 12종 중 기관 업무에 바로 쓰는 것 — 슬라이드(사업설명회·센터장 보고), 문서(사업계획서·결과보고서), 와이어프레임·UI 목업(7교시 대시보드 설계), 리서치(만족도 조사), 색상+서체(홍보물 톤 통일).

⑦ 코드 탭 — 자동화 앱 배포 (6~7교시)

터미널은 개발자용, 코드 탭은 일반인용. 저장소를 고르고 프롬프트 한 줄이면 시작이다.
  1. 첫 화면 파일은 반드시 index.html로 저장 (한글 파일명은 웹 주소에서 깨짐)
  2. github.com 가입 → 우측 상단 + → New repository → 이름 입력 → Public 선택 → Create
  3. 저장소 페이지에서 Add file → Upload files → index.html 끌어다 놓기 → Commit changes
  4. Settings → Pages → Branch: main / (root) → Save (최초 배포 1~2분)

주소는 https://내아이디.github.io/저장소이름/ 형태. 업데이트할 땐 index.html만 다시 올리면 1~2분 후 자동 재배포됩니다.
